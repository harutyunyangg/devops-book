# DevOps ուսումնական ձեռնարկ

Հայերեն, գործնական DevOps ձեռնարկ, որը զարգանում է սովորելու ընթացքում։

## Սկսել

1. Տեղադրիր Python 3.11+։
2. Տեղադրիր կախվածությունները. `python -m pip install -r requirements.txt`
3. Բացիր տեղային կայքը. `mkdocs serve`
4. Բրաուզերում անցիր `http://127.0.0.1:8000` հասցեով։

## Կայքի օգտագործում

Նախագիծը MkDocs-ով կառուցված ստատիկ կայք է (Material theme). Կայքը `docs/` պանակի Markdown ֆայլերից է առաջանում, իսկ պատրաստի արդյունքը հայտնվում է `site/` պանակում։ Ընդհանուր կառուցվածքը.

- `docs/` — աղբյուր բովանդակություն (նավիգացիան՝ `mkdocs.yml`-ի `nav` բաժնում)։
- `site/` — build-ի արդյունքը. ստատիկ HTML, որը կարող ես բացել ցանկացած բրաուզերում կամ տեղադրել web server-ի վրա։

### Դիտել մշակման ընթացքում (dev server)

Յուրաքանչյուր փոփոխություն ավտոմատ արտացոլվում է.

```bash
mkdocs serve
```

Բացիր `http://127.0.0.1:8000` , փոփոխությունները պահպանելիս էջը ինքնուրույն թարմանում է։ Ավարտելու համար սեղմիր `Ctrl+C`։

### Build և դիտել վերջնական արդյունքը

Պատրաստի (production) կայք ստանալու համար.

```bash
mkdocs build
```

Արդյունքը ընկնում է `site/`. Այն կարող ես դիտել՝ կա՛մ ուղղակի բացելով `site/index.html` բրաուզերում, կա՛մ՝ ցանկացած ստատիկ web server-ով. օրինակ՝

```bash
# Python-ի built-in server-ով
python -m http.server 8000 --directory site
# ապա բրաուզերում՝ http://127.0.0.1:8000
```

> **Խորհուրդ.** Բոլոր ստուգումները հանձնելուց առաջ գործարկիր `mkdocs build --strict`, որպեսզի MkDocs-ը նախազգուշացնի ցանկացած broken link կամ բացակայող ֆայլի մասին `site/`-ը տեղադրելուց առաջ։ Այս հրամանը նշված է նաև `AGENTS.md`-ում։

### Դիտել site-ը GitHub-ում

Եթե repository-ն միացված է GitHub Pages-ին, deploy-ից հետո կայքը հասանելի է `https://<username>.github.io/<repo>/` հասցեով։ Քանի դեռ Pages-ը միացված չէ, օգտվի՛ր վերը նշված տեղային մեթոդներից (`mkdocs serve` կամ `python -m http.server`):

## Աշխատանքային ցիկլ

Սովորիր մեկ թեմա զրույցով, արա լաբորատոր փորձերը, ապա օգտագործիր այս հրամանը.

> Թարմացրու DevOps ձեռնարկը՝ այս զրույցի հիման վրա։ Թեման՝ `<թեմա>`։ Ավելացրու միայն քննարկմամբ կամ փորձարկմամբ հաստատված գիտելիքը։ Պահպանիր էջի հաստատված կառուցվածքը, ավելացրու lab, իրական DevOps իրավիճակ, հարցազրույցի հարցեր և ինքնաստուգում։ Նախ ցույց տուր փոփոխությունների plan-ը, ապա կիրառիր այն։

Ամեն նոր նյութի համար AI-ը պետք է փոխի համապատասխան `docs/` Markdown ֆայլը և, անհրաժեշտ լինելու դեպքում, `mkdocs.yml`-ի navigation-ը։
